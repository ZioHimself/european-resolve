# Phase 04.1: Registration Confirmation Emails — Research

**Researched:** 2026-07-30
**Status:** Complete

## Executive Summary

Phase 04.1 closes two gaps in the email confirmation flow: (1) SMTP credentials are not passed to Cloud Run in production, and (2) the combined `POST /api/fundraiser/register` endpoint never sends a confirmation email. The existing email infrastructure is solid — nodemailer transport, HTML template with UA branding, 5 locale files, and a `sendConfirmationEmail()` function all exist. The work is wiring up deployment secrets and adding a parallel fundraiser email template.

## Gap 1: SMTP Credentials Not Deployed

### Current State

- `backend/src/config.ts` reads SMTP env vars: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` (lines 27-35)
- `backend/src/services/email.ts` gracefully handles missing credentials — `getTransporter()` returns `null`, and `sendConfirmationEmail()` logs a warning and returns early
- `backend/.env.example` documents the SMTP config with `smtp.mailbox.org:465` as provider
- `.github/workflows/deploy-backend.yml` deploys to Cloud Run with `env_vars` block (lines 62-66) but ONLY passes: `SPREADSHEET_ID`, `CORS_ORIGINS`, `WHYDONATE_WIDGET_URL`, `NODE_ENV`
- **Result:** Emails silently fail in production because SMTP config is empty strings

### Fix

Add 5 SMTP env vars to the Cloud Run deploy step in `deploy-backend.yml`, sourced from GitHub Secrets:

```yaml
SMTP_HOST=${{ secrets.SMTP_HOST }}
SMTP_PORT=${{ secrets.SMTP_PORT }}
SMTP_USER=${{ secrets.SMTP_USER }}
SMTP_PASS=${{ secrets.SMTP_PASS }}
SMTP_FROM=${{ secrets.SMTP_FROM }}
```

GitHub Secrets (not Variables) because `SMTP_PASS` is sensitive. All 5 should use `secrets.*` for consistency, though only `SMTP_PASS` strictly requires it.

### Manual Step Required

After deployment, the team must add these 5 secrets to the GitHub repository settings (Settings > Secrets and variables > Actions > Secrets). Values from `.env.example`:
- `SMTP_HOST=smtp.mailbox.org`
- `SMTP_PORT=465`
- `SMTP_USER=info@european-resolve.org`
- `SMTP_PASS=(actual mailbox.org app password)`
- `SMTP_FROM=Run for Ukraine 2026 <info@european-resolve.org>`

DNS (SPF/DKIM/DMARC) is already configured per user confirmation.

## Gap 2: Fundraiser Email Missing

### Current State

- `POST /api/register` (Track A) calls `sendConfirmationEmail()` at line 165-176 of `register.ts` using fire-and-forget pattern: `.catch((err) => console.error(...))`
- `POST /api/fundraiser/register` (Track B combined flow) at lines 232-364 of `fundraiser.ts` creates both a fundraiser AND registration but **never calls any email function**
- The standalone `POST /api/fundraiser` endpoint is not used by the frontend (confirmed by user)

### Existing Patterns to Follow

1. **Email data interface**: `RegistrationEmailData` in `render.ts` — 7 fields (name, email, participantId, tierName, amountEur, rewards, donationUrl)
2. **HTML template**: `renderConfirmationEmail()` in `render.ts` — builds HTML as template literal with inline styles, UA branding (blue header `#0057b8`, gold accent `#ffd700`, paper background `#f5f2eb`)
3. **Locale type**: `EmailLocale` in `locales/types.ts` — 15 string fields, all registration-specific
4. **Locale resolution**: `getEmailLocale(localeCode)` returns locale object, falls back to English
5. **LANGUAGE_TO_LOCALE mapping**: `types.ts` maps `"English" → "en"`, `"French" → "fr"`, etc.
6. **Interpolation**: `interpolate(template, params)` replaces `{key}` placeholders
7. **HTML escaping**: `escapeHtml()` for XSS prevention in email content
8. **Fire-and-forget**: Email sending does not block the API response

### Fundraiser Email Design

The fundraiser email needs to include:
- **All registration details** (same as existing email): participant ID, tier, amount, rewards, donation CTA
- **Fundraiser-specific section**: fundraiser page URL, edit link, display name, goal

#### Edit Link URL Structure (from frontend)

From `FundraiserConfirmation.tsx` (line 33-34):
```
const shareableUrl = `https://european-resolve.org/events/2026-run-for-ukraine/fundraiser?by=${slug}`;
const editUrl = `${shareableUrl}&edit=${editToken}`;
```

So the edit URL pattern is: `https://european-resolve.org/events/2026-run-for-ukraine/fundraiser?by={slug}&edit={editToken}`

#### New EmailLocale Fields Needed

Extend `EmailLocale` interface with fundraiser-specific strings (approximately 7-8 new fields):
- `fundraiserSubject` — email subject line for fundraiser confirmation
- `fundraiserIntro` — intro paragraph mentioning both registration and fundraiser creation
- `fundraiserHeading` — section heading for fundraiser details
- `fundraiserPageLabel` — label for the shareable page URL
- `fundraiserEditLabel` — label for the edit link
- `fundraiserEditHint` — warning to save the edit link (it's the only way to edit)
- `fundraiserDisplayNameLabel` — label for the fundraiser display name
- `fundraiserGoalLabel` — label for the personal fundraising goal

#### New Files/Functions Needed

1. **`FundraiserEmailData` interface** in `render.ts` — extends RegistrationEmailData with: `slug`, `editToken`, `displayName`, `goalEur` (fundraiser goal), `siteUrl`
2. **`renderFundraiserEmail()` function** in `render.ts` — produces HTML with both registration details table AND fundraiser details section
3. **`sendFundraiserEmail()` function** in `services/email.ts` — parallel to `sendConfirmationEmail()`, calls `renderFundraiserEmail()`

#### Template Approach

Keep templates self-contained (not partials). The fundraiser email reuses the same visual structure as the registration email but adds a fundraiser section between the registration details and the donation CTA. This avoids introducing abstraction complexity for only 2 templates.

### Integration Point

In `fundraiser.ts`, after the registration and fundraiser creation are complete (around line 362, before the return statement), add:

```typescript
sendFundraiserEmail(
  {
    // registration fields
    name: fullName!.trim(),
    email: email!.trim().toLowerCase(),
    participantId,
    tierName: tier.name,
    amountEur: tier.price,
    rewards: tier.rewards,
    donationUrl: config.donationUrl,
    // fundraiser fields
    slug,
    editToken,
    displayName: displayName!.trim(),
    fundraiserGoalEur: goalEur,
    siteUrl: config.corsOrigins[0] ?? "https://european-resolve.org",
  },
  language as Language,
).catch((err) => console.error("[email] Failed to send fundraiser confirmation:", err));
```
