**New gate pattern** (from RESEARCH — capture-phase click, not in codebase yet):

```typescript
function attachTierAmountGate(
  shadow: ShadowRoot,
  id: string,
  minAmount: number,
  tierName: string,
): () => void {
  const btn = shadow.querySelector(".wd-part-step-one-next");
  const errorEl = shadow.getElementById(`donation-amount-error-${id}`);
  if (!btn || !errorEl) return () => {};

  const handler = (event: Event) => {
    const amount = readAmount(shadow, id); // base amount only, not tip
    if (amount < minAmount) {
      event.preventDefault();
      event.stopImmediatePropagation();
      errorEl.style.display = "block";
      errorEl.style.visibility = "visible";
      errorEl.innerText = `Minimum donation for ${tierName} is €${minAmount}. Please enter at least this amount to continue.`;
      return;
    }
    errorEl.style.display = "none";
    errorEl.style.visibility = "hidden";
  };

  btn.addEventListener("click", handler, true);
  return () => btn.removeEventListener("click", handler, true);
}
```

## Shared Patterns

### Optional-prop gate scoping (registration vs visitor)
**Source:** RESEARCH gate scoping table + `FundraiserPage.tsx` (lines 416-422)
**Apply to:** `WhyDonateWidget`, `ConfirmationPanel`, `FundraiserConfirmation`

Gate activates only when **both** `minTierAmount` and `minTierName` are passed. Registration panels pass them; `FundraiserPage` visitor donate and post-payment invoice widget omit them.

### sessionStorage amount stash
**Source:** `src/lib/whydonatePaymentRedirect.ts` (lines 1-33) + `WhyDonateWidget.tsx` `persistDonationDetails`
**Apply to:** `WhyDonateWidget` pre-fill (D-09)

```typescript
export const PAYMENT_AMOUNT_STORAGE_KEY = "r4u:donation-amount";
// Pre-fill must call persistDonationDetails immediately after setInputValue, not wait for user input
```

### Backend authoritative effective tier
**Source:** ADR-009 + `confirm-payment.ts` pass-through
**Apply to:** `backend/src/tiers.ts`, `backend/src/services/sheets.ts`

Client gate is UX-only (D-13 bypass). Backend always computes tier from `recordedAmount` via `getEffectiveTier()`.

### Never substitute registered tier price for observed amount
**Source:** `backend/src/services/sheets.ts` (lines 215-218)
**Apply to:** all confirm-payment paths

```typescript
// The amount actually paid can differ from what was registered for
// — never substitute the registered tier price as if it were the paid amount.

  donatedAmount != null && donatedAmount > 0 ? donatedAmount : undefined;
```

### Reward string splitting
**Source:** `backend/src/tiers.ts` (lines 33-37)
**Apply to:** `getCumulativeRewards`

```typescript
return getEmailLocale(localeCode)
  .tierRewards[tierId].split(" · ")
```

### `'use client'` + CSS Modules confirmation panels
**Source:** `ConfirmationPanel.tsx`, `FundraiserConfirmation.tsx`
**Apply to:** frontend components only; gate error styling is inline in shadow DOM (not project CSS Modules).
